# 当前状态与奖励体系快照

> 用途：给外部设计方（人或 AI）做奖励体系重构时的**现状基线**。
> 所有字段与规则均从代码实测提取，不是设计意图。日期：2026-11-14，版本：`v1.0.0`（代码已含批次 A/B/C）。
> 对应提交：`62d7366`。

---

## 1. 技术底座（决定能做什么、不能做什么）

| 项 | 现状 |
|---|---|
| 运行形态 | Electron 桌面端 + 同一套渲染层的纯静态网页版（Vite 构建） |
| 渲染层 | 原生 JS（ES module），**无框架**、无运行时依赖 |
| 持久化 | 单一 `localStorage` 键：`nw_client_state_v1`（内部 `version: 3`） |
| 网络 | **零请求**。没有后端、没有账号、没有支付、没有真实下载 |
| 内容 | 18 款虚构游戏的元数据随代码分发（`data/games.js`），**不进 localStorage** |
| 测试 | `node:test`，67 个用例；视觉基线 26 张（13 场景 × 1920×1080 / 1280×720） |

**硬约束**：任何奖励机制必须能在「纯本地、无网络、可离线、可随时清空」的前提下运行，且判定结果只依赖本地状态（不能依赖时间流逝、随机数、服务器）。

## 2. 状态结构（`nw_client_state_v1`，version 3）

```js
{
  version: 3,

  library: {                      // 已拥有/已安装的作品
    [gameId]: {
      gameId, status,             // status: 'owned' | 'downloading' | 'installed'
      ownedAt, installedAt,       // ms 时间戳 | null
      progress,                   // 0..1
      favorite,                   // boolean
      lastLaunchedAt,             // ms | null
      launchCount,                // number
    }
  },

  downloads: [{                   // 下载队列（历史记录也在这里）
    id, gameId, stage,            // stage: QUEUED|PREPARING|DOWNLOADING|VERIFYING|INSTALLING|SHORTCUT|COMPLETED|CANCELLED
    resumeStage, progress, paused,
    stageElapsedMs, stageDurationMs, totalElapsedMs,
    queuedAt, startedAt, completedAt,
    speedMBps, etaSec,
  }],

  settings: {
    reducedMotion, soundEnabled, notificationsEnabled, defaultRoute,
    showAdult,                    // boolean，是否在商店显示 18+ 条目
    adultGate,                    // 'unset' | 'passed' | 'declined'
    adultGateAt,                  // ms | null
  },

  profile: {
    welcomeSeen, revealSeen, firstRevealGameId, ownerType,
    badges: [{ badgeId, unlockedAt }],
    stats: { completedDownloads, launchTotal, simulatedWaitMs },
  },

  wallet: { balance, spent },     // 心意：balance 初始 66，spent 累计送出

  gifts: [{ gameId, amount, at }],// amount ∈ {6, 18, 66}

  survey: null | { q1, q2, ownerType, submittedAt },

  events: [{ ts, event, gameId, extra }],  // 上限 500 条，超出裁最旧
}
```

**状态更新只有一个入口**：`store.js` 的 `dispatch(mutator)`。它负责：写入 → `localStorage` 持久化 → 通知订阅者 → **统一补发徽章**（见 §4）。

## 3. 目录数据模型（`data/games.js`，18 款）

```js
{
  id,                 // kebab-case，同时是素材目录名
  name, emoji,
  category,           // 8 个枚举之一，见下
  isAdult,            // boolean，必填且必须显式声明
  gradient: [..],     // 素材降级用的渐变色
  hook, desc, tags[], // 文案
  sizeMB, rating, owners,
  publisher, developer, releaseDate, playtimeHrs, lastPlayed,
  assets: { icon, portrait, header, hero, logo, screenshots[3] }
}
```

分类枚举（`data/categories.js`，唯一真源）：`rpg / shooter / action / strategy / simulation / casual / horror / tools`。

**注意**：`sizeMB`、`rating`、`owners` 是**虚构常量**，不随时间变化；`playtimeHrs` / `lastPlayed` 是展示用静态值，**不是真实游玩数据**。

## 4. 现有徽章（8 枚，全部已实现并在线）

| id | 名称 | 条件文案 | 判定依据（代码实际读取） |
|---|---|---|---|
| `first_download` | 首次下载 | 完成任意一款游戏的下载与安装 | `profile.stats.completedDownloads >= 1` |
| `first_launch` | 初次启动 | 启动任意一款已安装的游戏 | `profile.stats.launchTotal >= 1` |
| `shelf_three` | 小有收藏 | 让 3 款游戏进入你的库 | `Object.keys(library).length >= 3` |
| `shelf_all` | 架上无空 | 集齐当前目录的全部作品 | `Object.keys(library).length >= GAMES.length`（**随目录增长自动变难**，现为 18） |
| `first_reveal` | 揭开封面 | 第一次走完「安装完成」后的揭示页 | `profile.revealSeen === true` |
| `first_gift` | 心意初赠 | 向任意一款游戏送出一次心意 | `gifts.length >= 1` |
| `launch_ten` | 老玩家 | 累计点击「开始游戏」10 次 | `profile.stats.launchTotal >= 10` |
| `survey_done` | 如实作答 | 完成并提交一次体验反馈 | `survey && typeof survey.ownerType === 'string'` |

### 判定机制（重要，重构时必须保留或替换等价机制）

```
evaluateBadges(state)  // 纯函数，只读状态，返回「当前满足」的全部徽章
        ↑
store.dispatch() 里统一调用 → 与 profile.badges 求差集 → 写入新解锁（含 unlockedAt）
```

四条设计约束：
1. **幂等**：同一个徽章只会解锁一次，`unlockedAt` 不变。
2. **不重入**：徽章补发发生在 `dispatch` 内部，不在订阅回调里再次 `dispatch`。
3. **不回收**：已解锁的徽章不会因为条件不再满足而消失（例如卸载游戏后 `shelf_all` 仍在）。
4. **可测试**：`evaluateBadges` 是纯函数，67 个用例里有 8 个直接测它。

## 5. 心意（钱包）系统

| 项 | 值 |
|---|---|
| 初始余额 | 66（`WALLET_START`） |
| 面额 | 6 / 18 / 66 三档，其他值一律拒绝 |
| 扣减 | `balance -= amount`，`spent += amount` |
| 不足 | 拒绝且**不改状态**（返回 `{ ok:false }`） |
| 补充 | `refillWallet()` 补到 66，仅在低于 66 时可用，重复调用返回 `{ ok:false, reason:'心意已满' }` |
| 记录 | 每次送礼写 `gifts[]` + 一条 `gift_send` 事件 |
| 与现实的关系 | **完全虚拟**，不涉及支付、不可提现、无价值 |

## 6. 事件流（`events[]`，上限 500）

已实现的事件名（18 种）：

```
welcome_accept   acquire          download_pause   download_resume
download_cancel  download_complete launch          uninstall
favorite_change  reveal           survey_submit    data_export
gift_send        wallet_refill    badge_unlock     adult_toggle
adult_gate_pass  adult_gate_decline
```

每条结构：`{ ts, event, gameId|null, extra|null }`。

**这是唯一现成的「行为日志」**。如果新奖励体系要做「完成 X 次 Y 行为」，最省事的接入点就是它——但注意它**只保留最近 500 条**，不能当永久账本。

## 7. 下载状态机（奖励触发点都在这里）

```
QUEUED → PREPARING → DOWNLOADING → VERIFYING → INSTALLING → SHORTCUT → COMPLETED
                                                    ↓
                                            （任意阶段可取消 → CANCELLED）
```

- 同一时间只有一个「活动任务」，其余排队。
- 暂停/继续可作用在排队与活动任务上。
- 完成后写 `profile.stats.completedDownloads++`、`simulatedWaitMs += totalElapsedMs`。
- 单文件时长由体积决定（`<6000 MB` 走 60–80s，否则 80–100s），可用 URL 参数 `?downloadScale=0.02` 加速（测试用）。

## 8. 版本与迁移（改状态结构时必看）

```js
const legacy = !raw || raw.version !== 2 && raw.version !== 3;
```

- 当前 `version: 3`。**如果新增字段要升到 4，必须同步改这行判断**，否则 v4 存档会被当 v1 处理，误跑收藏迁移，数据会错。
- 只加字段、不改结构时（例如批次 6 加的 `wallet` / `gifts`），**不需要升 version**，`normalize()` 会补默认值。
- `normalize()` 是白名单式：类型不符即回落默认，坏档不崩、不默认放行（例如 `adultGate` 只认三个枚举值）。

## 9. 奖励重构的扩展点（按改动成本排序）

| # | 想做的事 | 改哪里 | 成本 |
|---|---|---|---|
| 1 | 加/改徽章条件 | `data/badges.js` 加条目 + `state/badge-rules.js` 加一行判定 | 低（纯函数，加完即有测试价值） |
| 2 | 加奖励数据字段（积分、等级、经验） | `emptyState()` + `normalize()` 白名单 + `dispatch` 内计算 | 中（三处必须同步，漏一处会被 normalize 丢掉） |
| 3 | 加新的行为触发 | `state/store.js` 对应动作里 `pushEvent` | 低 |
| 4 | 心意 ↔ 奖励打通（积分兑换、打赏返积分） | `sendGift` / `setAdultGate` 等动作 + 新增字段 | 中 |
| 5 | 奖励要在界面上展示 | `pages/library.js`（徽章墙）、`pages/detail.js`（心意区）、新增页面需注册路由 | 中高（会动视觉基线） |
| 6 | 改徽章视觉（图标/分组/稀有度） | `badges.js` 加字段 + `.badge-tile` 样式 | 低 |

### 必须避免的四个坑

1. **不要在订阅回调里 `dispatch`**——会重入，且徽章补发逻辑本身就依赖「dispatch 内统一处理」。
2. **不要用时间流逝做判定**（如「连续登录 7 天」）——本项目完全离线，没有可信时钟，且会破坏纯函数可测性。
3. **不要把奖励数据写进 `games.js`**——那是随代码分发的静态目录，改了等于改版本；玩家的进度必须在 `localStorage`。
4. **不要改动 `shelf_all` 的语义而不加过渡档**——它现在直接等于「18 款全收」，目录再涨会难到不可能。
